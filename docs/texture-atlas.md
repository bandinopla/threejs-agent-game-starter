# Texture atlas
the system for defining and creating texture atlases consist on creating an box empty object in the blender file, and assigned a custom property "atlas" to said object with the value being a string to name the atlas. The view must be always with the camera on top looking down. The childs have to be basic blender plane meshes with the material assigned to them. You can scale and rotate this planes to fit them in the atlas box. Everything inside the box will be what the atlas texture will contain. Each child represents the new area of the UVs for the materials using that texture.

Once you run `node optimize.js <name>`, images based on `atlas.userData.size` are created. For each child, the diffuse, roughness/metallic, and normal maps are placed into the generated textures according to the child plane's position, rotation, and scale. This allows a visual definition of the texture atlas. The script creates the textures and updates the UVs of every object using the child plane's material. In the final `public/<name>.packed.glb`, meshes in that atlas share the generated atlas material and textures. See [GLB export and optimization](glb-optimization.md) for the required end-to-end workflow.

## UVs of particles
Some objects like prites and quad particles expect a texture and assume UVs to be in the range from 0-1 so I created a script to adjust and re-map the UVs .

- getSpriteTextureNode(textureOrQuad:Mesh|Texture) : this function ( src/utils/getSpriteTextureNode.ts) will take a mesh or a texture and return a node that will sample the texture at the correct UVs. If it is a mesh, it is assumed to be a perfect quad that has a material from an atlas texture and it's UVs are inside of an atlas. NOT ROTATED. Else, it is the texture to use itself.
- getAtlasTextureOverlay( baseQuad:Mesh, overlayQuad:Mesh ) : this utility function serves to map textures that are supposed to be overlayed on top of another. Like for example the base color texture of the monkey and the blood texture. Both are textures that should be stacked on top of each other. But since their UVs have been packed, they no longer align nor ocuppy from 0-1. This function will calculate the needed transformation to make sure the uvs align when sampling the overlay texture to fit on top of the baseQuad texture. Usually in "baseQuad" you will pass a plane that has the base texture uvs, and the overlay will be the texture used to be placed on top of the base.
